# StayPilot 核心流程迭代与赛题对照报告

**当前结论：仿真商户中的完整交易闭环可执行；真实平台已具备一次运行的核心核验流程，但还不能自主完成真实预订与换订。** 本轮不是把真实查询包装为成交，而是让已采集的证据进入程序化评估，同时保持交易边界实际生效。

按用户要求，13:00 后不修改 GitHub。本轮迭代、测试与报告保留在本地，未推送远端；以下描述本地当前实现，不意味着冻结后的比赛提交代码已更新。

## 1. 这轮实际补齐了什么

新增入口：[`/live/workflow`](http://localhost:4173/live/workflow)。用户填写目的地、日期、人数、含税预算、步行与地铁直达上限、窗型、个人问题重要度及明确不可接受的问题后，可以运行实时只读核验，或重新评估雍和宫既有证据。

| 功能 | 新实现与保护 | 验收范围 |
| --- | --- | --- |
| 一次运行的跨平台核验 | 查询 FlyAI 与 RollingGo，匹配地图位置、读取房型并汇总评论来源 | 实时执行成功；最多检查 12 家位置、3 家 RollingGo 房型，不宣称覆盖全市场 |
| 精确通勤 | 景点与地铁站分开；匹配酒店名称与门牌，同名冲突保持未知；带门牌的景点优先于区级同名位置 | 真实查询核验 7 家路线；模糊或冲突位置没有自动猜坐标 |
| 窗型解释 | 分开记录无窗、内窗／暗窗、文字明确外窗、仅 API 有窗、未知 | 必须外窗时布尔“有窗”不能证明合格；有窗优先也不能压过预算 |
| 个人评论判断 | 权重与绝对禁忌分开；重复日期与相同内容去重；正反证据、日期、原始评分及评论总量保留 | 同一评论会因个人规则变化而改变结果；“重要”不会自动变成绝对排除 |
| 排序与缺口 | 先硬条件及通勤档位，再个人样本指标、展示价与通勤时长；未知评论不当作零风险 | 结果明确为待核验顺序；没有完整证据时最终推荐为空、所有候选不可成交 |
| 条件组合 | 根据实际路线提出公交或更长地铁直达的组合，最多三套，保留其他缺口 | 不自动加预算、不修改硬底线、不保证替代方案已可订 |
| Jev 合并证据判断 | 一次请求包含房型、路线、评论、缺口与个人规则；提供无匹配选项，结果绑定证据哈希 | 实际调用 jev-1.13.0 成功；模型只建议下一步核验，不控制授权、预算或交易 |
| 持续核验 | 首轮立即查询，之后每 30 真实分钟重新运行整个只读流程，带时区截止、最多 24 小时、可停止 | 启动、停止、进行中停止、重启不恢复已测试；没有做 24 小时真实运行或价格收益实验 |
| 可核对记录 | SQLite 保存运行结果、每条执行依据与前序哈希，可导出 JSON | 独立重算哈希链通过；哈希说明记录一致性，不证明原始平台事实永远真实 |

本轮还修复了两个会影响正确结果的问题：高德返回多个“雍和宫”时，原唯一匹配规则无法选择带门牌的景点；以及“有窗优先”把超预算的外窗套房排在预算内普通房之前。现在先寻找预算内满足硬条件的房型，再比较窗型偏好，避免把预算内候选误排除。北京取消时区过滤错误也已在前一轮修复并继续回归验证。另修复了文件读取失败后重复发送响应头导致的服务崩溃；故意请求不可读取的静态目标后，服务返回错误且后续接口保持可用。

## 2. 具体案例：10 月 9 日去雍和宫

住宿条件为 2026-10-09 至 2026-10-10，2 成人、1 间房、无儿童、含税总预算 600 元。有窗优先、可取消，卫生和隔音重要；允许地铁直达降级，只查询与测试。步行 20 分钟、地铁直达 40 分钟是核验参数，真实购买前还需写入明确授权。没有用户提供的首次预订或优化截止时间，因此本例不声称已验证真实按时成交。

### 原始真实观察的自动回放

原来分别查到的网页、API、地图与评论，如今能由一次运行自动合并成以下结果：

| 酒店 | 证据与判断 | 当前结果 |
| --- | --- | --- |
| 新侨饭店 | 原观察高级双床 558 元、无早、最多 2 人、10 月 6 日 00:00 前免费取消；原地铁直达约 37 分钟。近期评论有卫生、隔音、维护问题，与用户关注相关。窗型仍不明确 | 待核验，不能无条件推荐或购买；可以打开原评论和各条证据缺口 |
| 秋果（前门大栅栏） | 有窗精致大床 417 元示例无需待确认；410 元更低计划需待确认。地铁直达约 62 分钟，换乘约 57 分钟 | 本轮通勤参数不符合；可以提出延长地铁直达上限的待确认方案，但评论及最终费用仍缺失 |
| 世茂国际公寓（工体） | 同页面 531 元不可取消、585 元限时取消，585 元计划 10 月 8 日 18:00 前免费取消；落地窗。地铁换乘约 43 分钟、公交约 38 分钟 | 最低价不满足可取消要求；公交不在原降级范围内，须重新确认，会员优惠及最终费用仍需验证 |

这些价格都是当时展示价，**不是已经复核的含税成交总价**。通勤不是 10 月 9 日指定出发时刻的交通保证。新侨与世茂评论来自浏览器采集的历史定向样本；没有实时评论 API，也不能从差评标签估计全体住客问题发生率。

Jev 本轮实际读取上述合并证据，建议继续核验新侨，并优先取得最终报价。模型概率只是核验建议，未被转换为购买权限。

### 新一轮实时执行

2026-10-04 约 13:02—13:03 UTC+8，再次运行两平台与地图服务：程序保留 12 个候选，取得 7 家路线和 3 家 RollingGo 房型，单次核验约 45.7 秒。新侨当前路线约 36 分钟，程序仍找到 558 元房型并保留为待核验，而不会因优先看到 1,240 元外窗套房就错误宣告超预算。

本轮历史评论与新报价明确分开记录。对名称、门牌无法唯一匹配的酒店，路线仍为未知；飞猪详情房型未通过当前工具取得的酒店也没有冒用旧网页报价作为当前库存。45.7 秒不含此前浏览器采集评论时间，也不能用来宣称比真人节省某个百分比。

两个真实预订入口均实际返回 HTTP 403、`orderCreated=false`；测试钱包与订单前后未变。没有真实付款、取消或退款。

## 3. 完整交易闭环在哪个环境成立

独立仿真案例使用原有虚构杭州酒店目录、三个实际运行的网页、SQLite 订单及测试资金，**不是北京真实酒店订单**。浏览智能体实际访问页面、读取评论和报价、进入结算、提交请求；后端实际接受或拒绝测试交易。

本轮重新执行：

1. 确认测试授权后完成跨平台选择，取得平台 A 的 455 元可取消订单。
2. 推进 30 仿真分钟后发现竞品 315 元报价，先新订再取消旧单。
3. 退款未到账时，可用余额 230 元、占款 770 元；不能把待退款当可用钱。
4. 再推进 15 仿真分钟，455 元退款到账，可用余额恢复为 685 元，当前保留 315 元订单及相应净占款。
5. 在独立税费上涨场景中重新核验 1,555 元含税结算报价，服务端实际拒绝创建订单，测试钱包不扣款。

已有单元测试还覆盖：不可取消独立授权、余额不足、授权撤销及到期、报价变动、重复下单幂等、取消窗口边界、旧单取消失败与补偿、退款延迟／失败、截止无解、评论指令注入、资金冻结。长周期真实监控、真实付款及平台退款仍未通过生产服务验收。

## 4. 怎样对应赛题一

依据本地官方文件《HacKU 2026 — Problem Statements》的 “Give a Machine a Wallet – Agentic Commerce”。赛题要求明确一项消费决策、一个委托方、权限和实际执行的限制；演示完整交易及至少一次阻断，并提供可核验规则、日志、人工路线比较和带时间戳的费用证据。

| 赛题要求 | 我们对应的设计与证据 | 边界 |
| --- | --- | --- |
| 明确用户及具体消费痛点 | 用户委托酒店选择；有限预算下按个人容忍度降级，并利用可取消窗口继续优化 | 单目的地、固定日期；首版 1 房无儿童，不拆分入住 |
| 明确可以做和不可以做 | 授权单区分预算、占款、降级、取消权限、有效期；真实只读流程不具购买权限 | 用户确认的查询条件不等于真实购买授权 |
| 限制实际执行 | 提交交易时再次检查授权版本、期限、余额、含税总价、库存与取消规则；违规后端拒绝 | 仿真资金规则已执行；真实端点整体关闭 |
| 一次完整交易 | 网页发现 → 评论与规则 → 比较 → 结算 → 扣测试资金 → 确认订单；随后换订和退款账本可核对 | 完整成交证据属于自建测试商户和测试资金，不是真实 OTA 成交 |
| 至少一次被停止 | 税费超预算订单实际拒绝，账户不扣款；真实平台下单入口返回 403 | “模型说不能买”不能代替这些实际接口结果 |
| 决策规则及可查日志 | 授权 → 观察 → 评论 → 判断 → 动作 → 订单／退款；截图、来源、时间与哈希导出 | 展示可核验依据，而非声称公开模型内部思维 |
| 与人工路线比较 | 已有同市场手工操作路线的自动化回放基准，可比较步骤、耗时和测试订单成本 | 不是已招募真人实验；不能声称已证明真实节省时间或收益 |
| 费用必须观察并标时 | 真实价格、取消条款及模型结果保存观察时间；税费或会员优惠未证实则保留未知 | 没有编造税费、返现、积分价值，也没有计算未证实优惠收益 |

这条赛题对照支持展示“有执行边界的钱包委托”，而不是只展示酒店推荐聊天。它同时说明真实平台部分还缺什么，不能用仿真交易掩盖真实支付未开通。

## 6. 上线真实全流程还缺什么

优先补齐能影响成交的事实：最终含税报价、到店费用、人数和餐食、有效期与库存；其次取得稳定的评论读取来源与可核验的房型窗型、开业／翻新信息。平台端必须提供获准且可验证的订单、付款、取消、退款查询或沙箱能力，并绑定用户明确确认的购买授权。

当前已提供的 FlyAI、RollingGo、高德及 TypeSafe 凭证能支撑本轮只读验收；新增登录不会自动带来不存在的订单 API。生产交易权限、支付方式和入住人资料尚需按具体平台流程确定。取得接口后应先以平台沙箱验收订单、异常、撤销与退款对账，再启用真实购买。当前不保证全市场最低价，也不承诺尚未验证的真实成交、退款时效或用户收益。
