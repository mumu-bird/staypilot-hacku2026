## 可以直接发给平台的申请说明（未代发）

您好，我们正在开发StayPilot酒店选择与监控助手。已有飞猪FlyAI / RollingGo查询接入，并在北京雍和宫案例核验真实酒店、房型、取消窗口和地图路线。目前需要申请支持完整酒店交易的合作接口与独立沙箱，而不仅是搜索链接。

请协助确认下列能力、权限开通方式、文档及合作条件：

1. 最终报价与库存复核：绑定平台酒店ID、报价ID、日期、人数、房间数量、床型、餐食和取消政策，返回含税总价、所有必付费用、币种、有效期及可售状态。请说明报价ID是否会在不同查询间变化。
2. 创建订单：使用最终复核报价下单，提供平台确认号、确定的订单状态、付款方式及失败原因；支持幂等键或等效的重复提交保护。
3. 订单查询：能区分确认成功、失败、处理中和状态不确定，便于网络中断后的对账；明确接口超时后应如何查询实际结果。
4. 取消预览与提交：取得真实可退金额、手续费、截止时间及时区，按平台订单执行取消，并支持确认取消结果。
5. 退款查询：取得退款金额、状态和实际到账标识；需要明确取消成功与退款到账不是同一状态。
6. 独立沙箱：测试酒店、测试付款和测试订单；允许演示重复提交、报价变化、售罄、取消失败、退款延迟与结果不确定，且不产生真实扣款。
7. 酒店评论及房型信息：有可授权读取的评论原文、日期、评分尺度和样本量，以及外窗、最大入住人数、开业与翻新时间等字段吗？若无，请说明官方允许的人工核验/跳转方式。
8. 接入及运营：所需合作主体、审批流程、费用、配额、沙箱/生产认证、数据展示与缓存条件，以及API支持联系人。

我们的实现会保留预算和硬底线，由服务端拦截越权购买。取得沙箱后先验证完整订单与退款对账，再请求生产权限。当前不会尝试绕过未开放的交易能力。请提供适用于真实酒店预订的具体接口文档、沙箱申请入口及授权范围说明。

## 备选平台申请路径

Booking.com Demand API官方要求Managed Affiliate Partner，使用API Token及Affiliate ID。需要同时确认所获合作权限包含完整订单能力；不能把能搜索等同于能下单。官方申请前置条件：https://developers.booking.com/demand/docs/getting-started/prerequisites ，鉴权：https://developers.booking.com/demand/docs/development-guide/authentication ，沙箱说明：https://developers.booking.com/demand/docs/getting-started/try-out-the-api 。

本轮没有注册账户、发送申请或创建任何外部订单。Amadeus等其他平台尚未确认本项目所需的取消和退款能力，不作为已经可接入的完整替代方案。

## 接入后必须通过的验收

按真实平台沙箱验证：最终费用与预算边界、过期/改变报价、重复下单保护、订单状态不确定后的查询、取消窗口、取消失败时的保留与补偿、退款延迟期间的占款、退款实际到账后释放，以及撤销授权后的禁止新购买。沙箱成功后仍需生产权限和独立生产验收，不能把沙箱订单当成真实成交。
