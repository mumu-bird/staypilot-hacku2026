# 验收证据与运行范围

本表的交易场景使用仿真酒店、报价、评论、库存、订单及资金；独立飞猪页面使用真实只读数据，未启用真实订单或支付。Playwright 操作实际运行的网页；商户后端实际确认或拒绝测试订单，并通过 SQLite 保存资金与订单状态。

| 计划场景 | 可核验实现 | 当前证据 |
| --- | --- | --- |
| 三平台不同价格；不可取消房默认排除，单独授权后可订 | 原始评分、含税总价、取消条款分别显示；服务端检查独立权限 | 浏览器验收第 1、8 项，交易规则测试 |
| 同一差评对不同用户产生不同结论 | 原文与平台、日期、问题标签可打开；风险为问题比例乘个人权重 | 交易规则测试“a comment matters differently”，候选页原文 |
| 初筛无解、授权降级、预订后跨酒店优化 | 按用户排序逐级放宽；同档位且风险不增加；先新订后退旧 | 演示视频；浏览器验收第 1–3 项 |
| 税费超额、余额不足、取消过期或撤销授权实际阻止 | 后端重新核验报价、授权、资金和取消窗口 | 浏览器验收第 6、7 项；交易规则测试 |
| 截止无解，最多三组条件组合，无越权购买 | 仅使用实际观察过的证据；缺失事实不推定合格；旧报价标记重新核验 | 交易规则测试“no-solution deadline”“public deadline alternatives” |
| 重复下单、旧单取消失败、退款延迟／失败、报价变化 | 幂等请求、补偿取消、账本冻结、退款实际到账后释放 | 交易规则测试；浏览器验收第 2–4 项 |
| 决策过程可核对 | 页面截图、评论原文、规则与候选依据、授权版本、两种时间、哈希链导出 | `browser-verification.json`，`/api/audit/export` |
| 同一市场人工路线与智能体比较 | 相同种子、授权、预算与时钟；真实网页步骤计数 | `benchmark.md` 与 `benchmark.json`；人工路线为自动化回放，非真人实验 |

核心交易测试共 22 项。真实 Chrome 浏览器验收共 9 项。命令分别为 `npm test` 和 `npm run test:e2e`。额外的首次截止集成核验由 `npm run test:deadline` 单独执行，6 项通过，见 `deadline-verification.json`：11:59 最后核验、12:00 停止购买、三组有网页依据方案与审计哈希独立校验。

模型接口是可选配置：未配置服务时，界面明确显示规则驱动，评论问题使用仿真平台的明确标签。配置后，模型辅助提取须经过字段及原文摘录校验；预算与付款权限始终由后端规则决定。当前没有使用真实模型密钥执行线上模型验收。

本次交付包括本机可运行应用、公开源码、约 3 分钟的实际网页演示和可编辑 Pitch Deck。Dockerfile 是部署入口，当前机器未做 Docker 运行验收；没有宣称已上线真实预订服务。
