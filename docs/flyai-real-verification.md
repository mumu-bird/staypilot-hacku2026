- 自然语言搜索：明确询问房型、两晚含税总价、取消截止、评论原文及日期，要求仅查询。返回成功，但其生成文本明确表示这些核心成交字段不可提供。该文本的其他酒店介绍和距离叙述尚未逐项核验，不能作为规则已满足的证据。
- 网页链路：初始详情链接进入官方扫码页；随后沿链接内的官方 H5 地址打开，平台重定向到桌面酒店详情页。Chrome 使用已有登录状态，已读到房型、取消期限、218 条点评的计数，以及 10 条差评标签样本和近期正面评论。不再要求用户为这个样例扫码，未点击预订或提交订单。
- 新增本机页面 [飞猪真实验证](http://localhost:4173/live/fliggy)，可手动修改目的地、附近地点、日期并调用真实接口；显示酒店图片、搜索价格、评分原值、装修时间、观察时间和官方详情链接。仿真控制台侧栏也有入口。

| --- | --- | --- | --- |
| 万斯高空江景酒店（滨江龙湖天街店） | ¥666 | ¥666 | 4.00 |
| 全季杭州西溪古墩路地铁站酒店 | ¥330 | ¥324 | 0 |

两次相同条件调用观察到了价格差异；差异成因未验证，不把它推断为唯一的市场涨跌原因。`rate_desc` 结果出现中间夹有评分 0 的酒店，因此保留平台原值和顺序，不能保证结果满足评分排序。评分尺度、0 的含义和评论样本量未知；装修时间不等于开业时间，POI 搜索不证明步行或地铁可达。

## 仍缺的能力与事实

- 对应日期可订房型、库存、入住人数、餐食。
- 含税住宿总价及税费明细。
- 取消政策、取消截止时间、退款及到账状态。
- 搜索 API 缺评论原文、日期、评论数量和评分尺度；一个酒店已通过浏览器补充历史证据，其他酒店仍缺核验。
- 经核验的开业年份和目的地交通方式。
- 已获准的真实创建订单、取消和售后业务接口。

当前公开 CLI 提供搜索命令和预订跳转链接，尚未验证真实订单写入工具。另用 Bearer-only 请求 MCP 初始化和 `tools/list` 时得到 401。官方 CLI 附带额外签名及上下文并已调用成功，因此不能用这个 401 判断用户密钥失效；本次没有成功取得完整 MCP 工具列表，不能断言平台不存在其他业务权限。

## 下一步需要用户协助

1. 本样例无需再次登录或扫码；最终含税总价、餐食、人数和当前库存仍需具体报价核验。新增平台的合作凭证见 [申请清单](provider-onboarding.md)。
2. 如继续做完全自主预订，需要向平台确认本账号是否可开通订单创建、查询、取消、退款相关能力。可转交给平台的问题：是否提供沙箱订单？如何取得绑定日期、人数、餐食的含税报价与取消截止？是否有评论原文接口？有哪些可调用的订单和售后工具？
3. 真实下单前单独确定实际行程、商家、预算、入住信息及取消条款。当前只有查询验证授权。

## 实现与验证

- 服务端使用官方 CLI、固定搜索命令与校验后的参数，不向浏览器返回密钥，真实下单端点始终返回阻断，不调用商户写入接口。
- 关键字段缺失时 `transactionEnabled: false`；搜索价格不写入仿真报价，真实结果不消耗仿真钱包。
- 禁止脚本链接、非飞猪详情域名；日期格式和入住顺序在外部调用前校验。
- TypeScript 检查与生产构建通过；最新32项单元测试通过（含真实数据边界、监控停止/重启、评论容忍度及窗型授权测试）。
- 本机 HTTP 端点真实查询成功，返回 8 家酒店；查询前后测试钱包未变；真实下单端点返回 403，并带 `orderCreated: false` 和阻断理由。
- Chrome 实际点击“查询真实酒店”，验证 8 张真实酒店卡片、含税总价待核验提示及平台详情链接出现在页面上。
- 已扫描版本控制及非忽略文件，未发现本次用户密钥。公开交付不包含密钥、本机数据库或原始接口响应。

本机原始搜索、自然语言响应及接口冒烟验证记录位于被 Git 忽略的 `data/flyai-*.json`。凭证由服务器启动时读取；更新 `.env` 后需重启服务。
